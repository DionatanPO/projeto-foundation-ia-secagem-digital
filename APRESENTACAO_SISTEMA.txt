1. VISÃO GERAL
================================================================================

O AgroMind AI é uma solução de assistência técnica inteligente voltada
para o setor agrícola e industrial, com foco em:

  • Monitoramento de silos
  • Otimização de processos de secagem de grãos
  • Assistência técnica para operadores, agrônomos e equipes de manutenção

O sistema funciona 100% de forma local (on-premise), garantindo:

  ✓ Privacidade total dos dados
  ✓ Zero latência nas respostas
  ✓ Alta disponibilidade, mesmo em locais remotos sem internet
  ✓ Funcionamento offline completo

O sistema possui dois modos de operação:

  MODO LOCAL: Utiliza llama-cpp-python para rodar modelos GGUF quantizados
              diretamente na CPU ou GPU (CUDA/Vulkan/Metal)

  MODO REMOTO: Proxifica requisições para um servidor OpenCode
              (API compatível com OpenAI), suportando Claude, GPT-4o, etc.

4. FUNCIONALIDADES PRINCIPAIS
================================================================================

4.1 INTERFACE DE CHAT INTELIGENTE
─────────────────────────────────
  • Layout inspirado no Gemini/ChatGPT com visual moderno
  • Suporte a Markdown completo (tabelas, listas, cabeçalhos, código)
  • Blocos de código com syntax highlighting (highlight.js)
  • Cards de raciocínio expansíveis (processo de pensamento da IA)
  • Badge de métricas de performance (tokens/segundo, total de tokens, duração)
  • Indicador de digitação animado
  • Copiar respostas com um clique
  • Histórico de conversa (últimas 10 mensagens como contexto)

4.2 ENTRADA MULTIMODAL
──────────────────────
  • Texto: Campo de entrada com auto-expansão
  • Imagem: Upload de fotos para análise visual (silos, medições, painéis)
  • Voz: Ditado por voz em português (Web Speech API do navegador)
  • Atalhos: Enter para enviar, Shift+Enter para nova linha

4.3 MODO LOCAL (PRIVACIDADE TOTAL)
───────────────────────────────────
  • Modelos GGUF quantizados rodando localmente
  • Suporte a CPU e GPU (CUDA NVIDIA, Vulkan AMD/Intel, Metal Apple)
  • Troca dinâmica de modelos sem reiniciar o sistema
  • Descarregamento de modelos para liberar RAM/VRAM
  • Monitoramento em tempo real do consumo de memória

4.4 MODO REMOTO (FLEXIBILIDADE)
───────────────────────────────
  • Conexão com servidores OpenCode (API compatível OpenAI)
  • Suporte a modelos: Claude, GPT-4o, Gemini, e outros
  • Teste de conexão com status em tempo real
  • Configuração persistente (URL, modelo, toggle ativo/inativo)
  • RAG também funciona no modo remoto

4.5 RAG - BASE DE CONHECIMENTO
──────────────────────────────
  • Indexação automática de documentos na pasta documents/
  • Embeddings semânticos multilíngues (português otimizado)
  • Divisão inteligente de texto (chunks de 1500 tokens, overlap de 300)
  • Decomposição multi-query para consultas complexas
  • Deduplicação de resultados por relevância
  • Reconstrução do índice com um clique

4.6 INTERFACE DE CONFIGURAÇÕES (3 ABAS)
────────────────────────────────────────
  Aba 1 - Modelo Local:
    • Seletor CPU/GPU
    • Lista de modelos disponíveis (auto-detectada da pasta models/)
    • Botão de troca de modelo com animação de loading
    • Botão para descarregar modelo e liberar memória
    • Toggle de ativação do RAG
    • Botão para limpar e recarregar base vetorial
    • Slider de criatividade/temperatura (0.0 a 1.0)
    • Campo de diretriz do sistema (system prompt customizável)
    • Aviso de privacidade (dados 100% locais)

  Aba 2 - Modelo Remoto:
    • Toggle de ativação do modelo remoto
    • Campo de URL do servidor OpenCode
    • Campo de identificador do modelo
    • Botão de salvar configuração
    • Botão de teste de conexão
    • Comando copiável: opencode serve --port 4096
    • Aviso sobre envio de dados para servidores externos

  Aba 3 - Aparência:
    • Toggle entre modo escuro e claro
    • Preferência salva automaticamente no navegador
    • Detecção automática do tema do sistema

4.7 SEGURANÇA E AUTENTICAÇÃO
────────────────────────────
  • Sistema de chave de licença (APP_KEY) via variável de ambiente
  • Página de login com campo de chave de acesso
  • Sessões baseadas em Django
  • Dados nunca saem da máquina (modo local)

Formato de Streaming (NDJSON):
  {"event": "thought",   "data": "..."}   ← Raciocínio da IA
  {"event": "message",   "data": "..."}   ← Resposta do modelo
  {"event": "metrics",   "data": {...}}   ← Métricas de performance
  {"event": "done",      "data": null}    ← Fim do streaming

7. SERVIÇOS PRINCIPAIS
================================================================================

7.1 LMMService (Serviço de Modelo Local)
─────────────────────────────────────────
  • Padrão Singleton (uma instância, um modelo na memória)
  • Carregamento de modelos GGUF via llama-cpp-python
  • Detecção automática de GPU/CPU
  • Suporte multimodal (visão com CLIP mmproj)
  • Patch automático de templates de thinking (Qwen3.5)
  • Streaming com eventos NDJSON estruturados
  • Gerenciamento agressivo de memória (GC explicito)

7.2 RagService (Serviço de Base de Conhecimento)
────────────────────────────────────────────────
  • Padrão Singleton
  • Modelo de embedding: paraphrase-multilingual-MiniLM-L12-v2
  • Divisão de texto: SentenceSplitter (1500 tokens, 300 overlap)
  • Limpeza de documentos (remoção de números de página)
  • Persistência em disco (storage/)
  • Decomposição multi-query para consultas complexas
  • Resiliência no Windows (tratamento de file locks)

7.3 RemoteLLMService (Serviço de Modelo Remoto)
───────────────────────────────────────────────
  • Padrão Singleton
  • Integração com OpenCode Server (API OpenAI-compatible)
  • Gerenciamento de sessões (criação, envio, abort)
  • Persistência de configuração (RemoteConfig)
  • Teste de conectividade
  • Suporte a RAG mesmo no modo remoto
  • Formato de streaming NDJSON padronizado

10. COMO UTILIZAR O SISTEMA
================================================================================

10.1 INSTALAÇÃO
───────────────
  1. Instale as dependências:
     pip install -r requirements.txt

  2. Configure o arquivo .env com suas preferências

  3. Coloque os modelos GGUF na pasta models/

  4. Adicione documentos técnicos na pasta documents/ (para RAG)

  5. Execute as migrações:
     python manage.py migrate

  6. Inicie o servidor:
     python manage.py runserver

  7. Acesse: http://localhost:8000/

10.2 USO BÁSICO
────────────────
  1. Na página de login, insira a chave de licença (APP_KEY)
  2. No chat, digite sua pergunta ou use os chips de exemplo
  3. Para enviar imagens, clique no botão de anexar imagem
  4. Para ditado por voz, clique no botão de microfone
  5. Acesse as configurações pelo botão na barra lateral

10.3 MODO REMOTO
────────────────
  1. Abra um terminal e execute:
     opencode serve --port 4096

  2. Nas configurações, aba "Modelo Remoto":
     - Ative o toggle "Ativar Modelo Remoto"
     - Configure a URL: http://127.0.0.1:4096
     - Informe o modelo (ex: anthropic/claude-sonnet-4-5)
     - Clique em "Salvar" e depois "Testar"

10.4 RAG (BASE DE CONHECIMENTO)
────────────────────────────────
  1. Coloque documentos (.txt, .pdf, .md) na pasta documents/
  2. Nas configurações, ative o toggle "Base de Conhecimento (RAG)"
  3. Para reconstruir o índice, clique em "Limpar & Recarregar RAG"
  4. O sistema automaticamente consultará os documentos antes de responder
